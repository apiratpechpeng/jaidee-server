# เวอร์ชันรันทันที (ไม่ต้องติดตั้งอะไรเลย)

เวอร์ชันนี้ทำขึ้นมาเพื่อให้ **แค่มี Python ในเครื่องก็รันได้เลย** ไม่ต้อง `pip install`,
ไม่ต้องติดตั้ง PostgreSQL, ไม่ต้อง `npm install` — ใช้แต่ไลบรารีมาตรฐานที่มากับ Python
(`http.server`, `sqlite3`, `hashlib`, `urllib`) ทั้งหมด

ข้อมูลเก็บอยู่ในไฟล์ `depression_app.db` ที่จะถูกสร้างขึ้นอัตโนมัติในโฟลเดอร์นี้ตอนรันครั้งแรก
(SQLite เป็นฐานข้อมูลแบบไฟล์เดียว ไม่ต้องมีโปรแกรมฐานข้อมูลแยกต่างหาก)

## วิธีรัน (3 ขั้นตอน)

เปิด terminal ใน VSCode (`Ctrl+`` ) แล้วพิมพ์:

```bash
cd simple-python
python app.py
```

(บน Mac/Linux บางเครื่องอาจต้องพิมพ์ `python3 app.py` แทน)

จะเห็นข้อความ:

```
⏰ Reminder scheduler เริ่มทำงานแล้ว (ตรวจทุก 60 วินาที)
🚀 เซิร์ฟเวอร์รันที่ http://localhost:4000
🤖 โหมด AI: rule-based-fallback
```

เปิดเบราว์เซอร์ไปที่ **http://localhost:4000** ได้เลย — หน้าเว็บและ API อยู่ในเซิร์ฟเวอร์
เดียวกัน ไม่ต้องเปิด terminal ที่สองเหมือนเวอร์ชันอื่น

กด <kbd>Ctrl</kbd>+<kbd>C</kbd> ใน terminal เพื่อหยุดเซิร์ฟเวอร์

## ติดตั้งเป็นแอป (PWA)

เว็บนี้ตั้งค่าให้ "ติดตั้งเป็นแอป" ได้แล้ว (มีไอคอน เปิดแล้วเต็มจอเหมือนแอปจริง ไม่มีแถบที่อยู่เว็บ
ของเบราว์เซอร์) โดยไม่ต้องเขียนโค้ดเพิ่มหรือขึ้น Play Store/App Store เลย

**บนคอมพิวเตอร์ (ใช้งานได้ทันที):**
เปิด `http://localhost:4000` ด้วย Chrome หรือ Edge แล้วมองหาไอคอน "ติดตั้ง" (⊕ หรือรูปจอ
คอมพิวเตอร์มีลูกศร) ที่ช่องแถบที่อยู่เว็บด้านขวา กดแล้วเลือก "ติดตั้ง" — แอปจะเปิดเป็นหน้าต่างแยก
มีไอคอนของตัวเองในเครื่อง ไม่มี URL bar ให้เห็นอีกต่อไป

**บนมือถือ — มีข้อจำกัดที่ควรรู้:**
เซิร์ฟเวอร์นี้รันแบบ `http://` ธรรมดา (ไม่ใช่ `https://`) เบราว์เซอร์ส่วนใหญ่ (โดยเฉพาะ Chrome บน
Android) จะไม่ยอมให้ "ติดตั้งแอป" จากที่อยู่ `http://` ที่ไม่ใช่ `localhost` ด้วยเหตุผลด้านความปลอดภัย
ดังนั้นถ้าเปิดจากมือถือผ่าน IP ของคอมพิวเตอร์ในวง Wi-Fi เดียวกัน (เช่น `http://192.168.1.23:4000`)
อาจไม่เห็นตัวเลือกติดตั้ง ทางแก้ถ้าอยากลองบนมือถือจริงๆ:

- **iPhone (Safari):** กดปุ่มแชร์ (□↑) → "เพิ่มไปยังหน้าจอโฮม" ใช้ได้แม้เป็น `http://` ธรรมดา
- **Android (Chrome):** ต้องมี HTTPS ก่อน วิธีที่ง่ายที่สุดคือใช้เครื่องมืออุโมงค์ (tunnel) ฟรีอย่าง
  [ngrok](https://ngrok.com/) หรือ [Cloudflare Tunnel](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/)
  เพื่อได้ URL แบบ `https://...` ชั่วคราวที่ชี้มาที่เซิร์ฟเวอร์ในเครื่อง แล้วเปิด URL นั้นบนมือถือแทน
  (เป็นขั้นตอนเสริม ไม่ได้ตั้งค่าไว้ให้ในโปรเจกต์นี้)

## (ไม่บังคับ) ใช้ Gemini จริงแทนโหมดสำรอง

ค่าเริ่มต้นระบบใช้การวิเคราะห์แบบ rule-based (ไม่ต้องมี API key) ถ้าอยากให้ AI วิเคราะห์และ
ตอบแชทด้วย Gemini จริง:

1. ขอ API key ฟรีที่ https://aistudio.google.com/apikey (ล็อกอินด้วยบัญชี Google แล้วกด
   "Create API key")
2. คัดลอกไฟล์ `.env.example` เป็นไฟล์ชื่อ `.env` (อยู่โฟลเดอร์เดียวกัน)
3. เปิดไฟล์ `.env` แล้ววางคีย์ต่อท้าย `GEMINI_API_KEY=`
4. รัน `python app.py` ใหม่อีกครั้ง (ต้องหยุดเซิร์ฟเวอร์เดิมด้วย Ctrl+C ก่อน แล้วค่อยรันใหม่
   โค้ดจะไม่โหลดค่า .env ใหม่เองถ้าเซิร์ฟเวอร์ยังรันค้างอยู่)

## ทำไมถึงเรียบง่ายขนาดนี้

เวอร์ชันนี้ตัดทอนจากเวอร์ชันเต็ม (`backend-python/` + `frontend/`) โดยตั้งใจ:

| | เวอร์ชันนี้ (`simple-python/`) | เวอร์ชันเต็ม |
|---|---|---|
| ฐานข้อมูล | SQLite (ไฟล์เดียว ไม่ต้องติดตั้ง) | PostgreSQL (ต้องติดตั้ง + สร้างฐานข้อมูล) |
| Backend framework | ไม่มี ใช้ `http.server` ล้วนๆ | FastAPI (ต้อง `pip install`) |
| Frontend | HTML/CSS/JS ธรรมดา เสิร์ฟจากเซิร์ฟเวอร์เดียวกัน | React + Vite (ต้อง `npm install` แยก) |
| ต้องรันกี่ terminal | 1 | 2 |

ฟีเจอร์ครบเหมือนกันทุกอย่าง (สมัคร/ล็อกอิน, แบบประเมิน 9Q + AI วิเคราะห์, แชทบอท + สายด่วน 1323,
แจ้งเตือนรายสัปดาห์) เหมาะสำหรับตอนที่อยากลองรันดูเร็วๆ หรือยังไม่พร้อมติดตั้งเครื่องมือเพิ่ม
ถ้าอยากต่อยอดทำเป็นโปรเจกต์จริงจังในอนาคต ค่อยย้ายไปใช้เวอร์ชันเต็มทีหลังได้

## ทดสอบเส้นทางความปลอดภัย

ในหน้าแบบประเมิน 9Q ตอบข้อ 9 เป็นค่าที่มากกว่า "ไม่มีเลย" แล้วส่ง หรือในหน้าแชทพิมพ์คำอย่าง
"อยากตาย" — ทั้งสองทางควรขึ้นแบนเนอร์สายด่วน 1323 ทันที (ทดสอบจริงแล้วว่าทำงานถูกต้อง)

## โครงสร้างไฟล์

```

    security.py              เข้ารหัสรหัสผ่าน + session token

```

## การจับหัวข้อของแชทบอท (v11: keyword + NLP)

แชทบอทจับว่าผู้ใช้เล่าเรื่องอะไรแบบ 3 ด่าน (โค้ดอยู่ใน `backend/chatbot.py` ฟังก์ชัน `detect_topic_info`)

1. **keyword**: นับคะแนนคำสำคัญใน `KNOWLEDGE` ถ้าคำไหนมีคำปฏิเสธติดหน้า เช่น "ไม่ได้โกรธ" จะไม่นับ ถ้าคะแนนชัดมากก็ใช้ผลนี้เลย
2. **NLP ในเครื่อง** (`backend/nlp.py`): เทียบความคล้ายกับประโยคตัวอย่างใน `backend/topic_examples.py` แล้วรวมกับคะแนน keyword ไม่ต้องต่อเน็ตและไม่ต้องติดตั้งอะไรเพิ่ม
3. **Gemini**: ถ้าสองด่านแรกยังไม่มั่นใจ และมี `GEMINI_API_KEY` จะให้ Gemini เลือกหัวข้อ ถ้าไม่มี key หรือเน็ตล่ม ระบบใช้ผลจากในเครื่องแทน

**จำหัวข้อที่กำลังคุย (v12):** ข้อความสั้นๆ ต่อเนื่อง เช่น "อืม" "แล้วทำไงดี" "ก็ยังไม่ดีขึ้น" จะอยู่ในหัวข้อเดิม (`STICKY_BONUS`) หัวข้อใหม่ต้องชัดพอถึงจะเปลี่ยน ถ้ามี key และข้อความพอจะชี้ไปเรื่องใหม่ ระบบให้ Gemini ช่วยตัดสิน (`CHALLENGER_SCORE`)
**ไม่พูดซ้ำ:** ประโยคที่เคยพูดแล้วจะสลับเป็นประโยคอื่นของหัวข้อเดียวกัน ถ้าคำแนะนำของหัวข้อนั้นพูดครบแล้ว ใช้ชุด `OUT_OF_OPTIONS` (ชวนเลือกลองทีละข้อ / ปรึกษาคนที่ไว้ใจ) แทนการวนข้อเดิม

ข้อความวิกฤต (`backend/crisis.py`) ยังตรวจด้วย keyword แบบเดิมเสมอ ไม่ผ่าน NLP

- เพิ่มความแม่นยำ: เพิ่มประโยคตัวอย่างใน `backend/topic_examples.py`
- ปรับความไว: แก้ค่า `KW_WEIGHT`, `MIN_SCORE`, `SURE_SCORE` ด้านบนของ `detect_topic_info` ใน `chatbot.py`
- วัดผลหลังแก้: `python -m backend.test_topics -v`
- ในหน้าต่าง terminal จะเห็นบรรทัด `🔎 หัวข้อ=... (จาก ...)` บอกว่าแต่ละข้อความได้หัวข้อจากด่านไหน

## ภาวะวิกฤต, analytics และการวัดผล (v13)

- **ระดับวิกฤต** (`backend/crisis.py`): `HIGH` = พูดถึงการจบชีวิต/ทำร้ายตัวเอง/วิธีการชัดเจน, `MODERATE` = อยากหายไป/ไม่อยากตื่น/อยากหลับไปยาวๆ ทั้งสองระดับเปิด Crisis Protocol (ข้อความตายตัว + สายด่วน) เหมือนกัน
- **แบบประเมิน**: ภาวะวิกฤตดูจาก "ข้อ 9" เท่านั้น (1 คะแนน = MODERATE, 2 ขึ้นไป = HIGH) ไม่ดูคะแนนรวม ส่วนคะแนนรวมใช้บอกระดับอาการตามเกณฑ์ 9Q
- **Dual-output JSON** (`backend/analytics.py`): ทุกคำตอบแชทและผลแบบประเมินมี `analytics` + `user_response` (ข้อความ + `action_cards`) ระบบเราสร้างเอง ไม่ได้ให้ Gemini เขียน
  - ช่อง `phq9_score` เก็บคะแนน 9Q และ `depression_severity` แปลงจาก 9Q (ไม่มีระดับ Moderately Severe) ดูช่อง `severity_scale`
- **ปุ่มในแชท**: วิกฤต -> ปุ่มโทร 1323 / สะมาริตันส์ / 1669 ทุกครั้ง, เครียด/เศร้า -> ปุ่มหายใจผ่อนคลาย และปุ่มไปทำแบบประเมิน (อย่างละครั้งต่อบทสนทนา, ปุ่มแบบประเมินเฉพาะคนที่ยังไม่เคยทำ)
- **Log**: ตาราง `chat_analytics_logs` 1 แถวต่อ 1 คำตอบ ผู้ตรวจกรอก `human_crisis_label` (HIGH/MODERATE/NONE) เพื่อวัดผลจากข้อมูลจริง
- **วัดผล**: `python -m backend.evaluate -v` (ชุดทดสอบ) หรือ `python -m backend.evaluate --db` (ข้อมูลจริงที่ติดป้ายแล้ว)

## ชั้นความปลอดภัย (v14)

การตรวจข้อความทุกข้อความอยู่ใน `crisis.assess()` ทำงานตามลำดับ และ "ยกระดับได้อย่างเดียว" (ด่านหลังไม่มีทางลดระดับที่ด่านก่อนจับได้)

1. keyword (`crisis.py`) — HIGH / MODERATE
2. NLP เทียบประโยคตัวอย่าง (`crisis_examples.py` + ประโยคปัญหาทั่วไปใน `topic_examples.py` เป็นกลุ่มไม่เสี่ยง)
3. Gemini อ่านข้อความ (ถ้ามี key; ปิดได้ด้วย `GEMINI_CRISIS_CHECK=0` ใน .env) — ยังไม่ได้วัดผลกับ key จริง
4. ความเสี่ยงสะสมหลายข้อความ -> ถามเช็กอย่างนุ่มนวล + ปุ่ม 1323 (ครั้งเดียวต่อบทสนทนา)
5. พูดถึงข่าว/นิยาย/เพื่อน -> ยังนับเป็นวิกฤต แต่ตอบแบบถามกลับ + ปุ่มสายด่วน
6. เล่าว่าถูกทำร้าย/ล่วงละเมิด -> ข้อความตายตัว + ปุ่ม 1300, 1323, 191
7. อายุต่ำกว่า 18 ปี หรือไม่ทราบอายุ -> ข้อความวิกฤตแนะนำให้บอกผู้ปกครอง/ครู/ผู้ใหญ่ที่ไว้ใจ
8. ก่อนส่งข้อความไป Gemini ตัดเบอร์โทร อีเมล ไลน์ ชื่อโรงเรียน ฯลฯ (`privacy.py`) และห้าม Gemini วินิจฉัยโรค/ระบุขนาดยา

ทดสอบ: `python -m backend.test_safety`
วัดผลเต็ม: `python -m backend.evaluate --all` (เพิ่ม `--gemini` ถ้ามี key) -> `eval_reports/report.md`
ส่งออกข้อความให้ผู้เชี่ยวชาญติดป้าย: `python -m backend.export_for_labeling --blind`
ความสอดคล้องผู้ตรวจ 2 คน: `python -m backend.evaluate --kappa eval_reports/labeling_sheet.csv rater1_crisis rater2_crisis`

## แยกเรื่องหน้าฉากกับต้นตอ (v16)

- `root_cause.py`: ถ้าข้อความมีทั้ง "คน" (พ่อแม่ ที่บ้าน เพื่อน แฟน) และ "แรงกดดัน" (คาดหวัง เปรียบเทียบ ด่า ล้อ บังคับ) ที่ไม่ถูกปฏิเสธ
  หัวข้อหลักคือเรื่องคน (เช่น family_pressure) ส่วนเรื่องเรียน/งานเป็นหัวข้อรอง ถ้ามีแค่คำบุคคลเฉยๆ ไม่นับ
- `detect_topic_info()` คืนเพิ่ม `primary_topic`, `secondary_topic`, `confidence`, `needs_clarify` (คีย์เดิมยังอยู่)
- ข้อความแรกสั้น/กำกวม และยังไม่บอกต้นตอ -> ถามสำรวจก่อน ไม่ให้คำแนะนำ (แม้ผู้ใช้ขอ)
- คุยหลายข้อความ: ถ้าข้อความใหม่บอกต้นตอ หรือมี keyword ของเรื่องใหม่ชัดกว่า -> สลับหัวข้อทันที และเชื่อมกับเรื่องเดิม
- ตอนระบายไม่ใส่คำแนะนำ/ทางเลือกแล้ว จนกว่าผู้ใช้จะขอ
- Gemini ได้รับหัวข้อหลัก/รอง และ system prompt สั่งให้แยก Trigger กับ Root Cause ก่อนตอบ
- ทดสอบ: `python -m backend.test_topics -v` (ชุด dev) และ `python -m backend.evaluate --all` หัวข้อ 4 (ชุด blind)

- ความเร็ว: จำผลหัวข้อของข้อความเก่า / Gemini ตรวจวิกฤตเฉพาะข้อความที่มีสัญญาณและทำพร้อมกับการเตรียมคำตอบ
- terminal แสดง `⏱️ ใช้เวลา ... ms` ทุกข้อความ / หน้าเว็บ: กด F12 ดู Console `[jaidee] เซิร์ฟเวอร์ตอบใน ... ms`
- หน้าแชท: หน่วงระหว่างกล่อง 500 ms (เดิม 700) และแสดง "กำลังพิมพ์..." ระหว่างรอ

## คลังบทสนทนา (v19)

ไฟล์ใหม่ `backend/dialogues.py` เก็บบทสนทนา 5 สถานการณ์ที่ผู้พัฒนาทดสอบผ่าน (โครงงานประดิษฐ์, เพื่อนล้อต่อหน้าคนอื่น,
พ่อแม่ลำเอียง/ให้ดรอป/แฟนท้อง, วันเกิดและเกม, แม่ป่วยหนัก) ลำดับการตอบตอนนี้คือ:
วิกฤต (ข้อความตายตัว) → คลังบทสนทนา → ทักทาย/ขอบคุณ → คำกำกวม → คุยเล่น → จับหัวข้อแบบเดิม

- ข้อความที่คล้ายบทสนทนาในคลังและบริบทเข้ากัน จะใช้คำตอบจากคลัง (ไม่ส่งให้ Gemini แต่งใหม่) แต่ละ turn มีเงื่อนไขกันตอบผิดเรื่อง เช่น ต้องมีคำว่า "หมอ"
- คำกำกวม เช่น "ไม่เหลือใครแล้ว" "ไม่อยากอยู่บ้านนี้แล้ว" → ถามตรงๆ ว่าหมายถึงอะไร (ยังไม่ใส่เบอร์) ถ้าผู้ใช้ตอบรับ เช่น "ใช่" server จะเปลี่ยนเป็นโหมดวิกฤตพร้อมเบอร์ (crisis_source = check_answer)
- คุยเล่น/เรื่องดีๆ (วันเกิด ได้รางวัล เกม) ไม่ดึงหัวข้อปัญหามาตอบ ถามว่าบอทเล่นเกมไหม บอทบอกตรงๆ ว่าเป็นแชทบอท ชื่อที่ไม่รู้จักบอทบอกว่าไม่รู้จักแทนการแต่งข้อมูล
- หัวข้อใหม่: sibling_favoritism, dropout_pressure, unplanned_pregnancy, family_illness / เพิ่มเบอร์ 1663 (สายปรึกษาท้องไม่พร้อม) ในรายการเบอร์ที่อนุญาต
- ความยาว: คำตอบจากคลังไม่เกิน 3 กล่อง รวมไม่เกินประมาณ 650 ตัวอักษร (ราว 10 บรรทัดบนมือถือ)
- Gemini (ถ้ามี key) ได้ตัวอย่างจากคลัง 2 คู่ที่ใกล้ที่สุดไว้ดูน้ำเสียงและความยาว

ทดสอบ: `python -m backend.test_dialogues` (38 ข้อ รวมกรณีที่ต้องไม่ใช้คลัง และเช็กรูปแบบ/เบอร์โทร)
ข้อจำกัด: ชุดทดสอบนี้เป็นชุดสร้าง ไม่ใช่ชุดวัดผลจริง / turn ที่ status = "draft" ผู้พัฒนายังไม่ได้ทดสอบ / ทุกคำตอบยังต้องให้ผู้เชี่ยวชาญตรวจ

## แชทบอท v22 (ปรับทั้งระบบ วัดด้วยชุดทดสอบลับใหม่)

สิ่งที่แก้ (ปรับจากชุด dev เดิม blind_*.csv เท่านั้น ชุดเดิมจึงใช้รายงานผลไม่ได้แล้ว)

ข้อจำกัด: ชุดทดสอบลับใหม่ยังเขียนโดย AI คนเดียวกับที่แก้โค้ด ผลจึงอาจดีเกินจริง ต้องวัดซ้ำด้วยข้อมูลจริงจากหน้า /admin
ข้อความที่พูดถึงข่าว/นิยาย/คนอื่นยังถูกนับเป็นวิกฤต (ตั้งใจ: ตอบแบบถามกลับ + ปุ่มสายด่วน) และไม่ใช้กฎคำปฏิเสธในเรื่องวิกฤต

## แชทบอท v23 (เริ่มใหม่จาก v18: เข้าใจเรื่องที่เล่า แทนประโยคตายตัว)

เริ่มแชทบอทใหม่จากต้นฉบับ v18 แต่เก็บส่วนอื่นไว้ (หน้ายินยอม การเก็บข้อมูล /admin และการตรวจวิกฤตแบบ v22)
**ยกเลิกคลังบทสนทนาของ v19** (DIALOGUES ว่างแล้ว) ใช้ไฟล์ใหม่ `backend/story.py` แทน ซึ่ง "เรียนวิธีตอบ" จากบทบาทสมมติที่ผู้พัฒนาให้ผ่าน:

1. อ่านเรื่อง: เรื่องอะไร (โครงงาน รายงาน สอบ ดรอป ...) กับใคร (แม่ เพื่อนในห้อง ...) เวลา/วันส่ง ความถี่ ต่อหน้าใคร และชนิดความกังวล
   (กลัวไม่ทัน กลัวทำไม่ได้ ถูกล้อ/แกล้ง ลำเอียง ต้องตัดสินใจ ผลสอบ ป่วย ท้อง ทะเลาะ เหงา ความฝัน)
2. สะท้อนด้วยคำของผู้ใช้เอง เปลี่ยนคำแทนตัว ("แม่เรา" → "แม่ของคุณ") ไม่เดาความรู้สึกหนักเกินที่ผู้ใช้พูด
   ประโยค "ฟังดูหนักเลยนะครับ ช่วงนี้โครงงานกดดันคุณมาก" ไม่ใช้ตอนเริ่มคุยแล้ว
3. ถามต่อ 1 ข้อ ตรงจุดที่ยังไม่รู้ และยังไม่แนะนำจนกว่าผู้ใช้จะขอ ถ้าขอคำแนะนำตั้งแต่ข้อความแรกในเรื่องที่ต้องรู้รายละเอียดก่อน (ถูกแกล้ง ลำเอียง ป่วย) จะถามก่อน
4. ไม่มั่นใจ → สะท้อนสิ่งที่ได้ยินแล้วถามว่าเข้าใจถูกไหม
5. คำแนะนำเลือกข้อที่ตรงกับความกังวล (เช่น กลัวไม่ทัน → วางแผนย้อนจากวันส่ง) ผลแน่นอน ไม่สุ่ม

ทดสอบ: `python -m backend.test_roleplay` (36 ข้อ ทั้งข้อความเดิมจากบทบาทสมมติและข้อความที่พิมพ์ต่างไป ตรวจ "วิธีตอบ" ไม่ใช่เทียบประโยค)

1. **เล่ามีกี่เรื่อง:** แยกเป็นด้าน (เรียน ที่บ้าน เพื่อน แฟน อนาคต ตัวเอง การสูญเสีย) ถ้าเล่าหลายเรื่องในข้อความเดียว
   บอทสรุปทุกเรื่องแล้วถามว่าจะเริ่มเรื่องไหน (เรื่องด่วน เช่น ป่วย ท้อง ถูกทำร้าย คุยก่อนเลย) ถ้าเล่าเรื่องใหม่กลางทาง บอทบอกว่ายังจำเรื่องเดิมได้
2. **ปัญหาจริงคืออะไร:** ชนิดปัญหาเพิ่มเป็น 27 แบบ (ไม่เข้าใจงาน งานกลุ่มทำคนเดียว งานเยอะ พ่อแม่ทะเลาะ ถูกเปรียบเทียบ อกหัก ฯลฯ)
   และแยกคำที่หน้าตาเหมือนกันแต่ความหมายต่าง เช่น "ไม่เข้าใจงาน" กับ "ไม่มีใครเข้าใจเรา"
   ถ้าผู้ใช้ขอคำแนะนำแต่ยังไม่รู้ว่าติดตรงไหน บอทถามให้ชัดก่อน ไม่แนะนำแบบกว้างๆ
3. **ช่วยหาทางออกทีละขั้น:** เข้าใจปัญหา → ถามว่าลองอะไรไปแล้ว → ทางเลือก 3 ข้อที่ตรงปัญหา → ผู้ใช้เลือก → ขั้นแรกที่ทำได้วันนี้
   ถ้าผู้ใช้บอกว่าไม่กล้า/ทำไม่ได้ บอทเสนอก้าวที่เล็กกว่าเดิม ถ้าถามว่า "ควรเลือกทางไหน" บอทไม่ตัดสินแทน แต่ช่วยคิด

ถ้ามี GEMINI_API_KEY: Gemini เขียนคำตอบเองทั้งหมด โดยได้รับ "สถานะบทสนทนา" จาก manager.py (เรื่องที่เล่า กำลังคุยเรื่องไหน รอบนี้ต้องทำอะไร)
คำตอบของ Gemini ต้องผ่านการตรวจ (ห้ามวินิจฉัย ห้ามเรื่องยา ห้ามเบอร์แปลกๆ ห้ามพูดถึงคนที่ผู้ใช้ไม่ได้เล่า ยังไม่ถึงขั้นแนะนำห้ามแนะนำ) ไม่ผ่านใช้คำตอบของระบบเรา
วิกฤตยังใช้ข้อความตายตัวและเบอร์สายด่วนเหมือนเดิมเสมอ

## แชทบอท v26 (ชุดบทสนทนาที่สอง: สถานการณ์ 8-11)

ชนิดปัญหาใหม่ใน `story.py`: `cyber` (บัญชีปลอม แอบอ้าง เอารูป/ข้อมูลส่วนตัวไปเผยแพร่), `work` (ภาระงานของคนทำงาน เช่น ครู)
และเพิ่มคำของ `expectation` (อยากให้เรียน...), `compare` (ลูกป้าข้างบ้าน), `result` (คะแนนสอบแย่, เกรดก็ไม่ดี), `illness` (ติดเตียง), `money` (จนมาก)

ขั้นตอนใหม่ใน `manager.py` `FLOW` (ทุกคำตอบไม่เกิน 3 กล่อง 650 ตัวอักษร เนื้อหาที่ยาวแบ่งไปหลายรอบ):
- **8 ที่บ้านอยากให้เรียน X แต่อยากเรียน Y + ถูกเปรียบเทียบ + คะแนนไม่ดี**: รวมเป็นเรื่องเดียว สรุปแล้วถามว่าเรื่องคะแนนหรือเรื่องคณะหนักกว่า
  -> เรื่องคะแนน: วิธีบอก "ผลคะแนน + แผนแก้" / เรื่องคณะ: แยกความฝันกับความคาดหวัง หาข้อมูลทั้งสองทาง คุยตอนบรรยากาศดี
  -> ถามว่าพ่อแม่ฟังเหตุผลไหม -> ฟังได้: เตรียมข้อมูล / ใช้อารมณ์: ให้ครูแนะแนวเป็นคนกลาง
  **เป็นกลาง** (ตามที่ผู้พัฒนาเลือก): ไม่บอกว่าคณะไหนดีกว่า ไม่พูดไม่ดีถึงอาชีพใด ไม่แนะนำให้ตอบเนียนๆ
- **9 แกล้งทางออนไลน์**: แนะนำทันที (เก็บหลักฐาน, ไม่ตอบโต้+กดรายงาน, ให้ผู้ใหญ่ช่วย) -> แคปแล้ว: สำรองไฟล์ ประโยคเปิดเรื่องกับผู้ใหญ่
  และบอกว่า "อาจเข้าข่าย" ผิดกฎหมาย (ไม่ฟันธง) / ยังไม่แคป: บอกว่าต้องแคปอะไรบ้าง
- **10 ครูหมดไฟ**: แนะนำทันที 3 ข้อ -> ถามว่างานเอกสารหรือการตรวจงาน/เตรียมสอนหนักกว่า -> เคล็ดลับเฉพาะส่วนนั้น / ประโยคตอบงานด่วนแทรก
- **11 เสียพ่อแม่ + ดูแลผู้ป่วย + เงิน**: เสียใจด้วย + ขอความช่วยเหลือ (ครูแนะแนว, 1300, รพ.สต./อสม.) -> ถามเรื่องสิทธิ: พ.ร.บ.รถ, ประกันสังคม (1506)

ข้อเท็จจริงที่ตรวจจากแหล่งจริงก่อนใส่ (7 พ.ย. 2026):
- พ.ร.บ.คุ้มครองผู้ประสบภัยจากรถ: ทายาทขอค่าเสียหายเบื้องต้นกรณีเสียชีวิตได้ ยื่นภายใน 180 วัน ([KTC](https://www.ktc.co.th/article/auto/drive-maintenance/car-act-what-can-you-claim-atpb))
- ประกันสังคม ม.33/39 เสียชีวิต: ค่าทำศพ เงินสงเคราะห์กรณีตาย บำเหน็จชราภาพ ยื่นภายใน 2 ปี โทร 1506 ([Post Today](https://www.posttoday.com/smart-life/746527))
- 1300 ศูนย์ช่วยเหลือสังคม 24 ชม. ไม่มีค่าใช้จ่าย ([Find A Helpline](https://chat.findahelpline.com/organizations/1300-social-help-center-hotline-1300))
